# AI Gateway 使用指南

本文面向 AI Gateway 的普通用户，介绍安装、首次配置、Codex 与 cc-switch 接入、中转管理、配置备份和用量统计。

## 安装与升级

AI Gateway 提供两种 Windows x64 发布形式：

- NSIS 安装版：运行 `AI Gateway_<版本>_x64-setup.exe` 完成安装。
- 便携版：解压 `AI Gateway_<版本>_portable_x64.zip`，直接运行 `AI Gateway.exe`。

便携 ZIP 必须完整解压，不能只运行压缩包内的 EXE。程序需要 Microsoft Edge WebView2 Runtime；Windows 10/11 通常已经安装，缺失时请从 Microsoft 官方渠道安装。

安装版与便携版使用相同的应用标识，因此共享：

```text
%APPDATA%\com.ai-gateway.desktop
Windows Credential Manager
```

更新时先从托盘完全退出旧程序，再覆盖安装或替换便携目录。覆盖升级不会主动删除中转、密钥、日志、用量和路由配置。安装版与便携版不能同时运行，否则监听端口会冲突。

## 第一次使用

1. 启动 AI Gateway，确认运行状态显示本地网关已经监听。
2. 打开“中转管理”，新增一个第三方中转。
3. 填写名称、Base URL、API Key、优先级、超时和可选模型规则。
4. 保存后执行连接测试，确认密钥和地址可用。
5. 根据使用方式配置 Codex 或 cc-switch。

中转 Base URL 应指向服务商提供的 OpenAI 兼容入口，例如：

```text
https://gateway.example.com/v1
```

不要在文档、Issue、日志截图或 Git 仓库中公开真实 API Key。

## 中转管理

每个中转包含以下主要信息：

- 名称：用于界面、日志和用量归属。
- Base URL：第三方 OpenAI 兼容服务地址。
- API Key：保存到 Windows Credential Manager。
- 优先级：数字越小，未锁定时越优先。
- 启用状态：关闭后不参与新请求。
- 响应头超时：只限制连接、上传请求体和等待响应头，不限制响应体流的总时长。
- 模型规则：限制哪些模型可以选择该中转。

编辑中转时 API Key 留空表示保留原密钥。删除中转不会删除已经记录的历史用量，历史记录会显示为已删除线路。

手动锁定中转后，新请求优先使用该线路。已经开始的请求继续使用原来的上游连接。

## 本地访问令牌

AI Gateway 使用单独的本地访问令牌验证本机客户端。它和第三方 API Key 的职责不同：

| 凭据           | 使用位置                         | 作用                       |
| -------------- | -------------------------------- | -------------------------- |
| 本地访问令牌   | Codex 或 cc-switch 到 AI Gateway | 防止本机未授权进程调用网关 |
| 第三方 API Key | AI Gateway 到第三方中转          | 完成上游服务鉴权           |

Codex 集成使用：

```text
X-AI-Gateway-Token: <本地访问令牌>
```

其他 OpenAI 兼容客户端可使用：

```text
Authorization: Bearer <本地访问令牌>
```

本地鉴权通过后，专用令牌头不会转发给第三方。

## 监听端口

监听地址固定为 `127.0.0.1`，默认端口为 `8765`，允许范围为 `1024-65535`。

配置字段 Label 后的信息图标包含取值范围和生效方式说明。可以用鼠标悬浮或点击查看，也可以使用 `Tab` 聚焦图标；按 `Esc`、移出焦点或点击其他区域会关闭提示。保存错误和当前风险状态不会隐藏在提示中。

修改端口时，程序会先绑定新端口：

1. 新端口不可用时保存失败，数据库和旧监听保持不变。
2. 新端口可用时写入配置并启动新监听。
3. 旧端口停止接收新请求，既有流式请求可以正常结束。

切换成功后必须同步更新 Codex 或 cc-switch 的 Base URL。

## Codex 接入

Codex 配置路径优先使用 `CODEX_HOME`；未设置时使用：

```text
%USERPROFILE%\.codex\config.toml
```

### OpenAI 官方模式

- Codex 直接连接 OpenAI，不经过 AI Gateway。
- AI Gateway 不会对官方请求进行路由、健康检查或重试。
- ChatGPT 登录由 Codex 自己维护。
- 官方 Token 用量通过 Codex 本地会话记录只读同步。

### 第三方中转模式

- Codex 固定连接 AI Gateway 的本地 Base URL。
- 网关内部选择第三方中转并处理重试、熔断和用量。
- 切换第三方中转不需要重启 Codex，新请求立即生效。

官方和第三方都使用共享的 `custom` Provider。两种模式互相切换后，需要完全退出并重新启动 Codex。AI Gateway 只管理 `config.toml` 中属于自身的 Provider 配置；状态页只读检查 `auth.json` 中是否存在本地登录凭据，不会修改、备份或展示文件内容。

接入页只显示 Codex 桌面端、Codex CLI 和 ChatGPT 登录三项状态。ChatGPT“已登录”表示本机存在可识别凭据，不代表 AI Gateway 已联网验证凭据有效性。

如果检测到 CC-Switch 或其他工具正在管理 `custom` Provider，AI Gateway 会显示外部配置状态。不要让两个工具同时接管同一配置。

### 统一会话历史

“统一会话历史”用于把本地普通会话的 Provider 元数据统一为 `custom`，避免因 Provider 不同而从历史列表隐藏。

- 迁移前必须完全退出 Codex。
- 先扫描并查看预览，再由用户确认执行。
- 只修改 JSONL 第一条 `session_meta` 和本地线程索引。
- 不修改聊天正文；归档会话仍保持归档。
- 迁移前创建备份，并提供恢复最近一次迁移的操作。
- 包含 `encrypted_content` 的旧会话不保证可以跨供应商继续推理。

## cc-switch 接入

在 cc-switch 中新增 OpenAI 兼容 Provider：

```text
Base URL: http://127.0.0.1:8765/v1
API Key: AI Gateway 配置中心显示的本地访问令牌
```

常见错误：

- 只填写 Base URL 会返回 `401`。
- 填写第三方 API Key 而不是本地令牌也会返回 `401`。
- Base URL 通常应以 `/v1` 结尾，不要形成 `/v1/v1`。
- 修改 AI Gateway 端口后必须同步修改 cc-switch。

如果已经使用 AI Gateway 的“Codex 接入”管理 `custom` Provider，通常不需要再让 CC-Switch 接管 Codex 路由。

## 重试、熔断和自动切换

默认策略：

```text
额外重试次数：5
重试间隔：1 秒
最大累计等待：30 秒
允许自动切换中转：关闭
```

重试次数不设产品级上限，`0` 表示不重试。最大累计等待允许设置为 `0`，表示不限制累计等待并严格按照重试次数停止；设置为 `1–600` 秒时，达到等待预算会提前结束。配置很大的重试次数会延长单次请求生命周期，并产生更多日志和上游请求。

关闭自动切换时，请求只在当前中转重试。即使监控页显示“近期不稳定”，新请求仍会继续访问当前中转，不会被网关本地拦截。开启后，普通连接错误、408、429、线路级 5xx 和符合 413 策略的请求在当前中转重试耗尽后才可能尝试备用线路。

`No available channel for model/group`、模型容量不足和账号并发限制始终只重试当前中转，不熔断整个中转，也不自动切换。已经产生文本、推理或工具调用后，网关不会重放当前流式请求。

自动切换开启时，线路级熔断会在冷却期跳过异常中转；冷却结束后进入半开状态，下一次真实模型请求负责确认恢复。页面或手动测试显示“基础连接正常”只表示 `/models` 可访问，不代表此前失败的具体模型已经恢复。

“未识别临时错误兜底重试”只在尚未产生业务输出时生效，用于处理 HTTP 200 中的未知 `response.failed`、异常 SSE 或协议不完整。详细规则见[设计文档](design.md)。

## 请求体限制

本地请求体上限固定为 `200 MiB`，即 `209715200` 字节。程序先验证本地令牌，再读取请求体。

本地超限返回：

```text
HTTP 413
error.code = local_request_body_too_large
```

本地 413 不选择中转，不触发重试、熔断或自动切换。第三方真实返回的 413 才进入上游 413 策略。

## 用量统计

用量页面支持：

- 今天。
- 最多 30 个自然日的日期范围。
- 完整自然月，包括 31 天月份。
- `全部`、`OpenAI 官方`、`第三方中转` 和 `来源未确认`筛选。

第三方数据优先来自上游明确返回的 `usage`；缺失时使用与模型匹配的 `tiktoken` 编码估算输入和已经观察到的输出。估算数据会显示“含估算”或“估算”，不会伪装为服务商账单。重试和自动切换产生的每次实际上游调用分别归属实际访问的中转。

官方数据来自 Codex Desktop 本地 JSONL 中的 `event_msg.token_count`，不经过官方 API。程序优先扫描 `%USERPROFILE%\.codex`，并在 `CODEX_HOME` 指向其他有效目录时一并扫描。单条损坏、超大或不含计数明细的记录会被跳过，不影响同一文件后续用量同步。

`0.3.9` 首次启动会自动重建一次当前保留期限内的 Codex 用量。页面会显示官方事件、网关匹配、未唯一匹配、去重和失效清理数量；出现同步警告时可以执行“重建 Codex 用量”。Gateway 模式中无法唯一匹配网关请求的本地事件只保留诊断，不计入官方或第三方总量。

Codex/OpenAI 的输入 Token 已包含缓存命中：

```text
新增输入 = 输入 Token - 缓存命中 Token
总 Token = 输入 Token + 输出 Token
```

缓存命中和推理 Token 都是输入或输出的细项，不能再次加入总数。

页面显示总 Token、输入 Token、输出 Token和缓存命中 Token。缓存命中是输入 Token 的细项，不会再次加到总 Token；缓存命中没有明确上报值时不会本地猜测。官方线路固定显示在明细第一行，当前中转和已删除中转依次排列，来源未确认记录显示在最后。

用量默认保留 365 天，可配置为 30-3650 天。

## 配置备份与恢复

`.aigateway` 文件使用用户密码加密，适合跨电脑迁移。备份可包含：

- 中转配置和 API Key。
- 本地访问令牌。
- 路由、重试和健康探测设置。

备份不包含：

- 运行日志和健康历史。
- Token 用量历史。
- Codex 模式、会话和登录数据。
- `auth.json`。
- 本机监听端口。
- 开机启动状态。

导出使用 Argon2id 派生密钥，并用 XChaCha20-Poly1305 加密。密码不会保存在程序或日志中，忘记密码后无法找回，只能重新导出。

完整覆盖和合并导入都会保留目标电脑当前的监听端口。不要把备份文件提交到公开仓库。

## 日志和数据保留

运行日志会持久化到 SQLite，默认保留 7 天；退出程序后不会丢失。日志不记录 prompt、响应正文、API Key、Cookie 或完整请求头。

用量历史默认保留 365 天。缩短保留期限后，超期数据会被清理。

数据位置、安全边界和内部实现见[安全说明](../SECURITY.md)及[设计文档](design.md)。
