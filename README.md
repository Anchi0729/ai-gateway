# AI Gateway

AI Gateway 是一个 Windows 优先的本地桌面网关，用于管理 Codex 的 OpenAI 官方直连与第三方中转接入。Codex 在第三方模式下只连接固定的本地 OpenAI 兼容地址，中转选择、请求重试、健康探测、熔断和用量统计由 AI Gateway 统一处理。

当前版本：`0.3.10`

## 工作方式

```text
OpenAI 官方模式
Codex -> OpenAI 官方
         完全绕过 AI Gateway

第三方模式
Codex -> AI Gateway -> 第三方中转
```

官方模式使用 `openai` Provider，第三方模式使用 `ai_gateway` Provider；两个受管配置会同时保留，切换只改变 `model_provider`。旧版或外部工具使用的 `custom` 会被保留，不会被新逻辑主动覆盖。AI Gateway 只读检查 `auth.json` 中是否存在可识别的本地登录凭据，不会修改、备份或展示其中内容；官方登录仍由 Codex 自己管理。

## 核心功能

- 在 Codex 官方直连和第三方中转模式之间切换。
- 管理多个 OpenAI 兼容中转及其模型路由、优先级和健康状态。
- 默认在当前中转额外重试 5 次，自动切换中转默认关闭。
- 识别 HTTP、Responses SSE、模型容量和账号并发错误。
- 响应头超时不会截断已经建立的长时间 SSE 流。
- 统计第三方返回的 `usage`，并同步 Codex 本地记录的官方 Token 用量。
- 使用 Windows Credential Manager 保存第三方 API Key。
- 使用密码加密的 `.aigateway` 文件备份中转、密钥和路由配置。
- 优先使用 Codex 原生的跨 Provider 会话列表；旧版 Codex 不支持时提供手动兼容迁移。
- 同时提供 Windows NSIS 安装版和免安装便携版。

## 快速开始

1. 下载并启动 NSIS 安装版或便携版，二者不要同时运行。
2. 在“中转管理”中添加第三方中转，填写 Base URL 和真实 API Key。
3. 在“Codex 接入”中选择“第三方中转”，然后完全退出并重新启动 Codex。
4. 第三方中转之间的切换由网关内部完成，不需要重启 Codex。

默认本地地址：

```text
http://127.0.0.1:8765/v1
```

端口可以在配置中心修改为 `1024-65535`。保存新端口前会先检查能否绑定；失败时旧端口继续提供服务。

### cc-switch 接入

在 cc-switch 中添加 OpenAI 兼容 Provider：

```text
Base URL: http://127.0.0.1:8765/v1
API Key: 配置中心显示的本地访问令牌
```

这里填写的是 AI Gateway 的本地访问令牌，不是第三方中转的 API Key。真实中转密钥只在 AI Gateway 中配置。

## 重要默认值

| 项目         | 默认值      |
| ------------ | ----------- |
| 监听地址     | `127.0.0.1` |
| 监听端口     | `8765`      |
| 请求体上限   | `200 MiB`   |
| 额外重试次数 | `5`         |
| 重试间隔     | `1` 秒      |
| 最大累计等待 | `30` 秒     |
| Codex 流恢复 | `5` 次      |
| 自动切换中转 | 关闭        |
| 日志保留     | `7` 天      |
| 用量保留     | `365` 天    |

重试次数不设产品级上限，`0` 表示不重试。最大累计等待可设为 `0`，表示不限制累计等待并仅按次数停止；较大的次数会延长单次请求生命周期并增加日志和上游调用量。

配置中心字段 Label 后的信息图标用于显示取值范围和行为说明，可通过鼠标悬浮、点击或键盘聚焦查看；保存错误和当前风险状态仍会直接显示。

自动切换关闭时，内部熔断只作为“近期不稳定”提示，新请求仍会继续访问当前中转。只有开启自动切换后，连接、通用网关 5xx 和流传输等线路级故障才会让路由暂时跳过该中转。

模型或分组不可用、模型容量不足和账号并发限制始终只重试当前中转，不熔断整个中转，也不会扩散到备用线路。已经产生文本、推理或工具调用后的流式请求不会由网关重放，以避免重复内容、重复计费和重复执行工具；此后的 SSE 恢复由 Codex 按独立配置处理，默认 5 次。

## 数据与安全

- 本地服务只监听回环地址，不对局域网公开。
- 第三方 API Key 保存到 Windows Credential Manager，不写入普通日志。
- 转发第三方请求前会删除官方 Authorization、Cookie、账号、组织、项目和 `X-OpenAI-*` 身份头。
- 日志和用量记录不保存 prompt、响应正文或完整鉴权头。
- 官方用量来自 Codex Desktop 本地 `token_count`。解析器 v3 会在首次升级后自动重建一次保留期内的历史；输入 Token 已包含缓存命中，总 Token 等于输入加输出，不等同于 OpenAI 账单。Gateway 模式下无法唯一对账的本地事件只保留诊断，不计入汇总。
- 第三方用量优先采用上游 `usage`；缺失时使用 `tiktoken` 本地估算并明确标记，不等同于中转账单。
- 重试和自动切换产生的每次实际上游调用分别计入对应线路。
- 第三方模式下请求内容会发送给用户配置的中转服务，请只使用可信服务商。

安装版和便携版共用 `%APPDATA%\com.ai-gateway.desktop` 中的数据库，以及 Windows Credential Manager 中的中转密钥。删除便携目录不会删除这些数据。

## 开源发布检查

发布到 GitHub 前请确认仓库中没有 `auth.json`、数据库、`.aigateway` 备份、日志、安装包、用户截图或任何真实 API Key、令牌和请求内容。测试代码中的凭据只能使用明确的 `sample-*` 占位符。
